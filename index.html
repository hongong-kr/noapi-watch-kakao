취지 — 왜 이 절차인가

핵심: 공개 API가 없는 공공 웹페이지는 사람이 일일이 들어가 확인해야 새 소식을 압니다. 이 절차는 그 확인을 AI와 스크립트에 맡기고, 새 소식이 생겼을 때만 카카오톡으로 알려주는 흐름을 만드는 것입니다.

시의회 의안, 검토보고서, 국가 연구개발(R&D) 공고 같은 페이지는 대부분 공개 API를 제공하지 않습니다. 새 의안이 올라왔는지, 새 공고가 떴는지를 알려면 사람이 직접 페이지를 열고 목록을 훑어야 합니다. 페이지 전체를 보다 보면 배너나 카운터 같은 잡다한 변동에 시간을 쓰게 되고, 정작 중요한 새 소식은 올라온 시점을 놓치기 쉽습니다.

이 절차는 그 확인을 정해진 주기마다 자동으로 돌립니다. 페이지 전체를 비교하는 것이 아니라, 목록 표나 문단처럼 원하는 부분만 골라 봅니다. 변동이 없으면 아무것도 보내지 않고, 새 항목이 생겼을 때만 카카오톡 ‘나와의 채팅’으로 제목과 출처, 링크를 보냅니다. 작동자(사람)는 카톡만 확인하면 됩니다.

건네기 전과 건네고 난 뒤

  • 건네기 전: AI는 물어볼 때만 답합니다. 공공 웹페이지는 작동자(사람)가 직접 들어가 새로고침하며 확인해야 하고, 알림도 없습니다.
  • 건네고 난 뒤: 정해진 주기마다 정해진 페이지만 확인합니다. 원하는 부분만 골라 보니 관련 없는 변동은 알림으로 올라오지 않습니다. 변동이 없으면 침묵하고, 새 소식이 생겼을 때만 카톡이 옵니다. 무엇이 새로 생겼는지는 직전 기록과 비교해 남기므로, 나중에 “언제, 무엇이, 어디에 올라왔나”를 확인할 수 있습니다.
  • 작동자(사람)의 손이 덜 듭니다. 한 번 구축해 두면 토큰 갱신, 긴 글 나누어 보내기, 주기 실행은 에이전트와 스크립트가 맡습니다. 작동자(사람)는 설정이 바뀔 때만 답하고, 토큰이 완전히 만료됐을 때만 다시 인가 코드를 주면 됩니다.
한계도 분명합니다. 모든 공공 페이지에 바로 통하는 만능 감시가 아닙니다. 페이지 구조가 바뀌면 감시 범위를 다시 맞춰야 하고, 로그인이 필요한 페이지나 접근이 막힌 페이지는 이 흐름으로 감시하지 않습니다. ‘나에게 보내기’ 메시지의 푸시 알림 울림 여부는 공식 문서로 확인된 사항이 아니므로, 실제 폰에서 확인한 결과 그대로만 판단합니다.

이 흐름의 출발점은 2026-11-03 슬랙 잡담 채널의 GitHub 유용 도구 토론에서 소개된 changedetection.io입니다. 그 논의를 경량 감시 엔진으로 먼저 구현하고, Docker 배포는 선택지로 둔 것이 이 지시서입니다.

전체 흐름 한눈에 보기

핵심: 카톡 알림 통로를 먼저 만들고, 그 통로에 감시를 연결합니다. 감시 대상은 제안 카드를 보고 승인한 뒤에야 시작합니다.
  1. 카톡 구축

    카카오톡 ‘나와의 채팅’에 메시지를 보내는 기능을 동작 상태로 만듭니다. 작동자(사람)는 콘솔에서 직접 조작하고 키와 코드를 건네고, 폰에서 도착을 확인합니다.

  2. 감시 연결

    카톡 통로에 홈페이지 감시를 연결합니다. 기본은 가벼운 경량 엔진입니다. Docker 배포는 원할 때만 따로 진행합니다.

  3. 탐지

    정해진 주기마다 정해진 페이지를 확인합니다. 원하는 부분만 골라 보고, 직전 기록과 비교해 새 항목만 가려냅니다. 변동이 없으면 아무 메시지도 보내지 않습니다.

  4. 알림

    새 항목이 생겼을 때만 카톡으로 제목, 출처, 링크가 옵니다. 긴 글은 200자 한도에 맞게 190자 단위로 나누어 순차 발송합니다.

  5. 확인 · 재설정

    작동자(사람)는 폰에서 알림을 확인합니다. 감시 대상, 키워드, 주기, 알림 채널은 나중에 말 한 마디로 바꿀 수 있습니다. 바꾸기 전에는 변경 전·후 표를 보고 승인합니다.

지시서에는 이 흐름이 단계별 게이트(확인 지점)로 나뉘어 있습니다. 앞 단계 확인이 끝나지 않으면 다음 단계로 넘어가지 않는 규칙입니다. 작동자(사람)는 게이트마다 에이전트가 묶어서 묻는 질문에만 답하면 됩니다.

사람이 직접 해야 하는 일

핵심: 작동자(사람)가 하는 일은 다섯 가지뿐입니다. 콘솔 조작, 값 복사·전달, 폰 확인, 제안 카드 승인, 재설정 결정. 그 밖의 실행은 에이전트 몫입니다.

에이전트는 콘솔에 로그인하거나 클릭을 대신할 수 없습니다. 정확한 경로와 입력값을 알려주고, 작동자(사람)가 마친 뒤 결과 값만 받아 검증합니다. 키, 토큰, 인가 코드는 대화에 그대로 남기지 않고, 파일에만 안전하게 저장합니다.

1. 카카오 콘솔에서 로그인하고, 클릭하고, 동의하기

카카오디벨로퍼스 콘솔에서 앱을 고르고, 필요한 설정을 켜고, 동의 항목을 정하는 일은 작동자(사람)만 할 수 있습니다. 에이전트가 경로와 입력값을 알려주면, 그 순서대로 진행합니다.

작동자(사람)가 한다

콘솔 로그인, 앱 선택 또는 새로 만들기, 설정 켜기와 저장, 동의 항목 설정, 동의하고 계속하기 클릭.

AI가 한다

어디에서 무엇을 켜고 저장할지 경로와 입력값을 순서대로 알려주고, 전달받은 값이 빠지거나 틀리지 않았는지 검증합니다.

리다이렉트 URI와 메시지 링크 도메인은 등록값과 요청값이 끝 슬래시까지 같아야 합니다. 다르면 오류가 납니다. 이 부분은 지시서에 따로 주의 사항으로 들어 있습니다.

2. 키와 인가 코드를 복사해 에이전트에게 전달하기

REST API 키와 인가 코드는 콘솔과 브라우저 주소창에서만 볼 수 있는 값입니다. 작동자(사람)가 복사해 에이전트에게 건넵니다. 인가 코드는 수 분 안에 만료되므로, 받자마자 바로 다음 단계로 넘어갑니다.

작동자(사람)가 한다

콘솔에서 REST API 키 복사, 브라우저 주소창에서 인가 코드 복사, Client Secret을 쓸지 말지 방침 정하기.

AI가 한다

받은 값을 파일에 저장하고, 빈 값이나 공백이 섞이지 않았는지 확인합니다. 이후 대화에서는 값을 그대로 다시 보여주지 않습니다.

기본 방침은 Client Secret을 ‘사용 안 함’으로 바꾸는 것입니다. 켜 둔 채로 쓰려면 Secret 코드를 에이전트에게만 전달합니다. 어떤 방침이든 지시서에 적힌 대로 파일에 반영됩니다.

3. 폰에서 실제로 도착했는지 확인하기

카톡이 실제로 왔는지, 알림이 울렸는지는 폰을 가진 사람만 확인할 수 있습니다. API 응답이 성공이라고 해서 끝이 아닙니다. 작동자(사람)가 “폰에서 도착했다”고 답해야 카톡 구축이 완료됩니다.

작동자(사람)가 한다

‘나와의 채팅’에 테스트 메시지가 왔는지, 푸시 알림이 왔는지(또는 안 왔는지) 직접 확인해 답합니다.

AI가 한다

테스트 발송 1통을 보내고 응답을 확인한 뒤, 작동자(사람)의 확인 답을 보고서에 그대로 적습니다. 알림 여부는 추측하지 않습니다.

4. 제안 카드를 보고 승인하기

감시를 시작하기 전, 에이전트는 감시 대상과 키워드, 주기, 알림 채널을 한 번에 보여주고 승인을 받습니다. 좋은 도구를 알았다고 임의로 설치하거나 자원을 쓰지 않는 것이 이 절차의 규칙입니다.

작동자(사람)가 한다

제안 카드를 보고 “예시 그대로 할지, 무엇을 빼고 더할지” 답하고, 확정 표를 보고 최종 승인을 합니다.

AI가 한다

예시 표와 자원 영향(무과금 여부, 부하, 알림량)을 함께 보여주고, 승인받은 값으로만 감시 설정을 만듭니다.

Docker 배포나 주기 변경, 확장 서비스처럼 새로 시작하는 일도 마찬가지입니다. 먼저 제안하고 승인을 받은 뒤에만 실행합니다.

5. 재설정을 결정하기

구축이 끝난 뒤에도 감시 대상, 키워드, 주기, 알림 채널은 바꿀 수 있습니다. 바꾸고 싶을 때 작동자(사람)가 말로 정하면, 에이전트가 현재 표와 변경 전·후 표를 보여주고 승인을 받은 뒤에 고칩니다.

작동자(사람)가 한다

무엇을 어떻게 바꿀지 말로 정하고, 변경 전·후 표를 보고 승인합니다.

AI가 한다

파일을 고치고, 무변동 실행과 시뮬레이션으로 다시 검증한 뒤 바뀐 설정 표와 검증 결과를 보고합니다.

자세한 말 예시와 절차는 아래 ‘나중에 바꾸는 방법’ 부분에 정리했습니다.

작동자(사람)는 지시서를 처음부터 읽을 필요가 없습니다. 에이전트가 묻는 것만 답하면 됩니다. 기본값이 있는 항목은 “기본값으로 진행”이라고 한 마디로 답할 수 있습니다. 기본값은 ‘나에게 보내기’만 구축하고, 경량 엔진만 쓰고, 2시간마다 확인하고, 카톡으로만 알리는 것입니다.

  • 행안부·국토부 소관 공고는 전수 수집합니다. 행정안전부, 국토교통부, 행안부, 국토부라는 말이 들어가면 키워드와 관계없이 수집하는 예시 방침입니다.
  • 그 밖의 공고는 두 가지 조건을 함께 만족할 때만 수집합니다. 실증, 테스트베드, 시범, 수요조사 같은 말과, 모빌리티, 자율주행, 교통, 도로, 시설, 안전 같은 분야 말이 둘 다 들어간 경우입니다. AX실증, 모빌리티, 자율주행, 스마트시티 같은 말은 그 자체로 수집 대상이 되는 예시입니다.
  • 의안·보고서는 목록의 새 항목만 새 소식으로 봅니다. 이미 본 항목의 사소한 문구 변동은 새 소식으로 알리지 않습니다.

처음 감시를 시작할 때는 기존 항목을 한꺼번에 알리지 않고, 현재 목록을 기록으로 저장한 뒤 종료하는 것이 기본값입니다. 처음부터 기존 항목까지 알림으로 받고 싶다면, 에이전트에게 미리 말해주세요.

알림이 오는 모습

핵심: 변동이 없으면 아무 메시지도 오지 않습니다. 새 소식이 생겼을 때만, 제목과 출처, 링크가 담긴 짧은 카톡이 옵니다.
  • 침묵 규칙: 감시에서 변동이 없으면 어떤 메시지도 보내지 않습니다. “변동 없음” 보고를 매번 보내지 않습니다.
  • 알림 문구: 한 건씩 짧게 만듭니다. 제목, 출처, 링크를 담고, 여러 건이 한 번에 생기면 건수를 먼저 알리고 건별로 나눠 보냅니다.
  • 글자 수 규칙: 카카오톡 텍스트 본문은 최대 200자입니다. 지시서의 발송 방식은 200자에서 여유를 둔 190자 단위로 나누어 순차 발송합니다. 문단 하나가 190자를 넘어도 안에서 다시 나눕니다. 긴 글을 한 번에 보내면 끝이 잘릴 수 있으므로, 이 나누기가 들어 있습니다.
  • 토큰 수명: 액세스 토큰은 6시간, 리프레시 토큰은 2개월입니다. 액세스 토큰이 만료되면 스크립트가 자동으로 갱신합니다. 리프레시 토큰까지 만료되면 인가 코드를 다시 받아야 합니다. 만료일과 다시 받는 절차는 인수인계 보고서에 적힙니다.
  • 주기: 기본값은 2시간마다, 홀수 시각 정각(01:00, 03:00, …, 23:00)입니다. 너무 짧으면 대상 서버와 폰에 부담이 되고, 너무 길면 늦게 알게 되므로, 원하는 주기가 있으면 에이전트에게 말해주세요.

알림에 들어가는 링크는 대상 페이지 주소를 그대로 씁니다. 메시지 안에 별도 링크를 넣으려면, 그 도메인을 미리 제품 링크 관리에 등록해야 합니다. 등록하지 않은 도메인은 발송에 실패할 수 있습니다.

두 가지 감시 방식

핵심: 기본은 가벼운 경량 엔진입니다. 대시보드 화면으로 직접 관리하고 싶을 때만 Docker 배포를 선택합니다. 둘 다 쓰면 대상이 겹치지 않게 나눕니다.

Track 1 — 경량 엔진 (기본값)

외부 패키지 설치 없이 Python 3 표준 라이브러리만으로 돕니다. 대상 페이지별로 맞춘 방식으로 목록을 뽑고, 필터를 적용하고, 직전 기록과 비교합니다. 정기 실행은 2시간 간격으로 등록합니다. 처음 쓰는 분은 이 방식만으로 시작하는 것이 기본값입니다.

Track 2 — Docker 배포 (선택)

사내 서버나 업무용 PC, NAS에 공식 changedetection.io를 띄워 웹 대시보드(포트 5000)에서 관리하는 방식입니다. 자바스크립트로 늦게 뜨는 페이지도 크롬 컨테이너와 함께 살펴볼 수 있습니다. Docker가 있는 환경이 어디인지 먼저 확인받고, 배포한 뒤에는 대시보드 접속과 필터·알림 설정을 확인합니다.

Docker 배포를 고르면, 감시 범위를 정하는 필터와 알림 URL 설정은 공식 화면에서 직접 정합니다. 감시 주기는 공공기관 서버 부담을 고려해 2시간에서 하루 1회 사이를 권합니다. Track 1과 Track 2가 같은 대상을 중복 감시하지 않게, 둘 다 쓸 때는 대상을 나눠 담당을 정하고 중복 알림이 오는지 확인합니다.

어떤 방식을 쓸지는 지시서를 건네기 전, 또는 건넨 뒤 에이전트가 물을 때 정하면 됩니다. “경량 엔진만”, “Docker까지”, “둘 다” 중 하나로 답해주세요.

비용, 그리고 확장 서비스

핵심: 이 절차의 기본 범위인 ‘나에게 보내기’는 무료입니다. 다른 사람에게 보내는 서비스는 심사, 채널, 비용 조건이 따로 붙으므로, 기본 구축에 섞지 않고 원할 때만 별도로 진행합니다.

금액은 부가세(VAT)를 더하기 전 기준입니다. 알림톡과 브랜드메시지는 카카오가 직접 파는 상품이 아니라 공식 딜러사(발송 대행사)를 통해 계약하는 구조라, 실제 단가는 딜러사와 발송 물량, 플랜에 따라 달라질 수 있습니다. 견적을 받을 때는 “성공 건수 기준인지, 실패 시 문자 대체발송 비용이 포함되는지”를 먼저 확인하세요.

나에게 보내기

무료 · 기본 범위

받는 사람은 로그인한 본인 1명입니다. 별도 심사가 없고, 일간·월간 쿼터(제공량) 범위 안에서 씁니다. 쿼터와 현재 사용량은 콘솔의 통계·쿼터 화면에서 확인합니다.

친구에게 보내기

무료 · 심사 필요

같은 앱에 로그인하고 동의한 카카오톡 친구에게 보냅니다. 1회 최대 5명까지입니다. 비즈앱 전환과 추가 기능 심사가 필요하고, 발송자와 수신자 모두 동의가 필요합니다. 사용자 간 주고받는 용도라, 서비스가 일방적으로 알림을 보내는 용도로 신청하면 심사에서 반려될 수 있습니다.

알림톡

공식 정산단가 8원/건 · 딜러사 판매가 6.5~13원대/건

전화번호를 아는 불특정 다수에게 친구 추가 여부와 관계없이 보낼 수 있습니다. 비즈니스 채널 개설과 템플릿 사전 승인이 필요하고, 정보성 메시지만 보낼 수 있습니다. 성공 건수 기준으로 과금되며, 실패 시 문자 대체발송 비용(SMS 약 15원, LMS 25~40원 수준)은 별도입니다.

브랜드메시지 (구 친구톡)

텍스트형 약 20~24원/건 · 자유형 100원/건

친구톡은 2025년 12월 31일에 종료됐고, 2026년 1월 1일부터 브랜드메시지로 전환됐습니다. 카카오톡 채널을 추가한 이용자에게 광고성·홍보 메시지를 보낼 수 있습니다. 크레딧(선불)·후불, 플랜과 딜러사에 따라 달라지며, 이미지와 형식에 따라 단가가 달라질 수 있습니다.

챗봇 (챗봇 관리자센터)

일반 상품 무료

이용자가 물으면 답하는 채널 전용 대화 도구입니다. 예전 이름은 ‘카카오 i 오픈빌더’입니다. 개인 카톡 계정이나 단체 채팅방에서는 쓸 수 없고, 채널을 개설한 뒤 챗봇을 만들고 배포합니다. 대화 자체는 무료지만, 스킬 서버 같은 외부 시스템 연동 비용은 별도입니다. 이용자가 먼저 말을 걸어야 대화를 시작합니다.

확장 서비스를 원하면, 에이전트가 조건과 비용을 먼저 보여주고 승인을 받은 뒤에 진행합니다. 승인 없이 비즈앱 전환이나 심사 신청, 채널 개설을 시작하지 않습니다.

나중에 바꾸는 방법

핵심: 구축이 끝난 뒤에도 에이전트에게 말 한 마디로 설정을 바꿀 수 있습니다. 에이전트는 현재 표를 보여주고, 변경 전·후 표에 승인을 받은 뒤에야 고칩니다.

에이전트에게 재설정을 맡기면, 에이전트는 바꾸기 전에 “지금 설정은 이렇습니다. 무엇을 어떻게 바꾸겠습니까?”라고 현재 표(대상, 키워드, 주기, 알림 채널)를 보여줍니다. 답을 받으면 변경 전·후 표를 보여주고 승인을 받습니다. 승인 뒤에야 파일을 고치고, 고친 뒤에는 무변동 실행과 시뮬레이션으로 다시 검증해 결과를 보고합니다.

바꿀 수 있는 것 — 말 예시

“감시 대상에서 IRIS를 빼줘.” · “○○ 공고 페이지를 새로 추가해줘. 주소는 …야.” · “키워드에 ‘○○’를 더해줘.” · “감시 주기를 4시간마다로 바꿔줘.” · “알림을 카톡 말고 슬랙으로도 보내줘.” · “알림은 제목만 짧게 보내줘.”

  • 감시 대상 바꾸기: 빼거나, 새로 추가하거나, 일부만 남기고 나머지는 끌 수 있습니다. 새로 추가하면 주소와 페이지 종류도 함께 확인받습니다.
  • 키워드·필터 바꾸기: 단어를 더하거나 빼고, 행안부 전수 수집을 끄고 키워드 조건으로만 모으는 식으로 바꿀 수 있습니다.
  • 주기 바꾸기: 4시간마다, 하루 1번 아침에만 확인하는 식으로 바꿀 수 있습니다. 주기를 바꾸면 정기 실행 등록을 다시 하고 다음 실행 시각을 알립니다.
  • 알림 채널 바꾸기: 카톡 외에 슬랙을 더하거나, 카톡을 끄고 슬랙만으로 바꿀 수 있습니다. 새 채널로 바꾸면 테스트 발송 1건을 보내 도착 확인을 받습니다.
  • 알림 문구·건수 바꾸기: 제목만 짧게 보내거나, 여러 건이 한 번에 오면 건수만 먼저 알리는 식으로 바꿀 수 있습니다.

대상을 뺄 때는 해당 기록 파일도 함께 정리할지 물어봅니다. 검증 없이 “바꿨다”고만 보고하지 않는 것이 이 절차의 규칙입니다.

내려받기 · AI에게 건네기

핵심: 지시서는 사람이 읽고 따라 하는 문서가 아닙니다. 내려받아 개인 AI에게 그대로 건네고, 에이전트가 묻는 것에만 답하면 됩니다.
  1. 지시서를 내려받습니다. 아래 버튼을 누르면 kakao-send-to-me-manual.md 파일이 저장됩니다.
  2. 개인 AI 에이전트에게 파일을 그대로 건넵니다. 내용을 요약하거나 편집하지 않고, 파일 그대로 건네는 것이 전제입니다.
  3. 에이전트가 묻는 것에만 답합니다. 앱 선택, 기본값 진행 여부, 키와 코드 전달, 폰 도착 확인, 제안 카드 승인 순서로 묻습니다. 모르는 항목은 “모른다”고 답하면, 에이전트가 그 항목만 따로 안내합니다.
  4. 완료 보고를 받습니다. 테스트 발송 확인, 감시 대상 확정 표, 스냅샷 저장, 시뮬레이션 검증, 리프레시 토큰 만료일과 재설정 방법이 보고서에 들어 있는지 확인합니다. 폰 도착 확인 없이는 완료로 보지 않습니다.

알아두면 좋은 주의점

핵심: 자주 막히는 지점은 등록값과 요청값이 어긋나는 경우와, Secret을 빼먹는 경우입니다. 둘 다 지시서의 오류 대응표에 원인부터 좁히는 순서로 들어 있습니다.
  • 주소 불일치 오류(KOE006): 리다이렉트 URI 등록값과 요청값이 끝 슬래시까지 같지 않으면 납니다. 등록값과 요청값을 대조하고, 다르면 다시 등록·저장한 뒤 인가 코드 발급부터 다시 합니다.
  • Secret 누락 오류(KOE010): Client Secret이 ‘사용함’인데 요청에 Secret이 없거나 다르면 납니다. Secret 포함 여부를 확인하고, 아니면 ‘사용 안 함’으로 바꾼 뒤 다시 요청합니다.
  • 본문이 잘리는 경우: 텍스트 본문 한도는 200자입니다. 에러 없이 잘릴 수 있으므로, 발송 전에 나누는 단위를 다시 확인합니다.
  • 401 오류: 액세스 토큰 만료(6시간)일 가능성이 큽니다. 스크립트가 자동으로 갱신합니다. 갱신도 안 되면 리프레시 토큰 만료로 보고 인가 코드 발급부터 다시 합니다.
  • 링크를 넣었는데 발송이 안 되는 경우: 링크 도메인이 등록되지 않았을 가능성이 큽니다. 도메인을 등록하거나 링크를 빼고 테스트 발송으로 원인을 나눕니다.
  • 매번 알림이 오는 경우: 기록 비교나 필터 범위에 문제가 있을 수 있습니다. 무변동 실행으로 다시 확인합니다. 새 소식을 놓치는 경우는 페이지 구조가 바뀌었을 수 있으니, 파서를 고친 뒤 시뮬레이션으로 다시 검증합니다.

실행 당일 콘솔 화면이나 단가, 쿼터가 지시서와 다르면, 에이전트는 실행 당일의 공식 문서를 따르고 달라진 점을 보고서에 적습니다. 지시서와 공식 문서가 다를 때 지시서를 고집하지 않는 것이 규칙입니다.
